# การส่งมอบฟีเจอร์โดยใช้ AI ช่วย

- **สถานะ:** ฉบับร่าง — รอการทบทวน
- **สร้างเมื่อ:** 2026-10-09
- **ขอบเขต:** กระบวนการทำงานวิศวกรรมส่วนบุคคล (ใช้ตัวอย่างทั่วไป ไม่มีข้อมูลลับของบริษัท)

## เป้าหมาย
สร้างฟีเจอร์ให้มีประสิทธิภาพด้วยความช่วยเหลือจาก AI โดยนักพัฒนายังคงรับผิดชอบผลลัพธ์และความถูกต้อง

## ขั้นตอนที่เสนอ
1. **รับงาน (Intake)** — อ่าน Requirement ระบุความกำกวม กำหนด Acceptance Criteria และ Use Cases
2. **สำรวจ (Explore)** — หา Repository, Architecture, Dependency และ Pattern เดิมที่ได้รับผลกระทบ
3. **วางแผน (Plan)** — แยกงาน เปรียบเทียบแนวทาง ระบุ Edge Cases และวางแผน Implement/Test
4. **ลงมือทำ (Implement)** — แก้ไขแบบเฉพาะจุดและติดตามสมมติฐานที่ใช้
5. **พิสูจน์ผล (Verify)** — ทำ Unit/Integration Test ตามความเหมาะสม ตรวจสอบแบบอิสระ และทดสอบด้วยมือเมื่อจำเป็น
6. **รีวิว (Review)** — รีวิว Diff แยกจากผู้ลงมือทำ และให้นักพัฒนาตรวจสอบข้อค้นพบกับพฤติกรรมสุดท้ายด้วยตนเอง
7. **ส่งมอบ (Deliver)** — Commit ตามรูปแบบที่ตกลง เปิด Draft Merge/Pull Request และเชื่อมโยงกับ Work Item

## กรณีหลาย Repository
ถ้าฟีเจอร์ครอบคลุมหลาย Repo ให้มี Feature Design ร่วมกันชุดเดียว พร้อมระบุการเปลี่ยนแปลงของแต่ละ Repo, Dependency ด้าน Version/Contract และผู้รับผิดชอบการทดสอบ อย่าคิดว่าเครื่องมือจะเห็น Repo ที่อยู่นอก Workspace โดยอัตโนมัติ

## คำสั่งสำหรับ Agent
ใช้ไฟล์ `AGENTS.md` ระดับโปรเจกต์ที่กระชับ เพื่ออธิบาย Convention และจุดเริ่มต้นของ Repo เก็บขั้นตอนแบบ Skill แยกจากไฟล์ดังกล่าว และโหลดตามจำเป็นจาก `puen-stack`

## ประเด็นที่ยังไม่ตัดสินใจ
- การกระทำใดให้ Automate ได้ และการกระทำใดต้องให้คนอนุมัติ?
- ควรสร้าง Skill ใดก่อน?
- จะติดตั้งหรือ Sync Skill ไปยังแต่ละ Workspace อย่างไร?
- ใช้มาตรฐาน Commit และ Template สำหรับ PR/MR แบบใด?
